# 能力墙重构 — 从「智能体广场」到「能力工作台」

> 2026-10-25 · 面向「TestMate 是 SSD 测试组的测试伙伴」这一定位，重新定义前端的信息架构。
> 目标读者：前端 / 后端 / 测试组同事。

---

## 一、为什么要改

当前首页叫「智能体广场」，卡片数据来自 `GET /api/v1/agents`，`agents` 表是**智能体注册表**。但这张表里真正能跑的只有一半：

| code | 名字 | 实际形态 | route |
|---|---|---|---|
| `log-analysis` | 日志分析 | **工具**（填参数 → 出结果） | 默认走 AgentRunner |
| `env-ops` | 环境运维 | 工具（建设中） | 同上 |
| `test-plan-gen` | 测试方案生成 | 工具（建设中） | 同上 |
| `testcase-gen` | 文本用例生成 | 工具（建设中） | 同上 |
| `code-review` | 代码检视 | **看板**（只读指标） | `page:code-review` |
| `agent-market` | AI 资产市场 | **目录**（可浏览的共享清单） | `page:market` |

知识库更进一步——它**根本不在卡里**，是侧栏跟「广场」平级的顶级项（`/kb-manage`）。

于是三个结构性问题：

1. **卡片按实现形态建模（agent），用户按使用意图感知（跑一个活 / 看一个盘 / 找一份资产 / 查一份知识）。** 两套坐标系不一致，用户每次都要重新判断"这个是不是智能体"。
2. **卡片元信息是假的。** 所有卡片统一显示 `🔧 引擎 / 📊 调用次数 / 🕐 最近调用`（`views/Plaza/AgentCard.vue`）——资产市场永远 0 次调用，代码检视没有引擎可言。
3. **知识库被抬成平级分区。** 用户看到的是"两个功能区"，不是"一堆能力"；而且「所有智能体共享的私有知识源」这句 lede 在知识库脱离智能体概念后已经不成立。

**根因**：卡片缺一个表达"交互形态"的字段。`category`（ssd-trace / ssd-spec / auto-code…）是**业务域标签**，跟形态正交，不能复用。

## 二、核心模型

### 2.1 一张卡 = 一项「能力」

> 统一主词：**能力**（用户层）。引擎层保留「智能体」（`agent.engine` = Dify / 内置），两者各归其位，不互相污染。

### 2.2 四种形态（kind）

`kind` 与 `category` **正交**：形态说"这东西怎么用"，域标签说"这东西管哪块业务"。

| kind | 名称 | 用户在做什么 | 卡片 CTA | 卡片 meta 行 | 详情页形态 |
|---|---|---|---|---|---|
| `tool` | 🛠 工具 | 填参数 → 出结果 | 开始使用 › | 引擎 · 最近使用 | 左表单 + 右结果 |
| `board` | 📊 看板 | 看指标，不改数据 | 查看看板 › | 数据源 · 覆盖量 | 只读看板 + 时间窗 |
| `catalog` | 🗂 目录 | 找/装/传共享资产 | 浏览资产 › | 资产数 · 待审数 | 筛选 + 列表 + 上传 |
| `library` | 📚 知识 | 管知识库存、检索 | 管理知识 › | 数据集 · 文档 · 分段 | 概览 + 检索 + 数据集 |

### 2.3 状态语义按形态重定义

`status` 字段（draft/alpha/beta/stable/deprecated）保留在后端，但**卡片上的徽标按形态换词**——对看板和目录说"Beta / 稳定"没有决策价值：

| kind | 徽标词 |
|---|---|
| tool | 规划中 / 内测 / 公测 / 可用 / 已下线 |
| board | 未接入 / 正常 |
| catalog | 正常 |
| library | 未接入 / 正常 |

### 2.4 知识库存的两层理解

- **第一层（本次落地）**：知识库从侧栏顶级项降级为**一张卡**，与其他能力同列，点进去仍是现有的知识库工作区（数据集 / 文档 / 分段 / 检索 / 对话）。
- **第二层（后续可选）**：每张能力卡可挂**专属数据集**（`dataset_id` 绑定 `capability_code`），让「日志分析」只检索指定知识源。需要后端加绑定表，本次不做。

### 3.1 四个区块的职责

1. **待办带（sticky 置顶）**——首页真正的职责是"告诉我今天该看什么"，不是"列功能"。只放**需要你行动**的事：资产待审 / 同步失败 / 知识库未接入 / 能力刚上线。每条可点击直达对应能力。
   **平台技术状态（RAGFlow / Dify / ReviewAgent）不上首页**——那是侧栏"服务状态"的活。
2. **形态筛选 + 搜索**——主筛选维度是**形态**（全部 / 工具 / 看板 / 目录 / 知识，带计数），状态筛选降级为工具条右侧下拉。
3. **能力网格**——3 列大卡（沿用现有 `.card` 视觉语言），**可用在前、规划中沉底**；组内按 精选 → 最近使用。
4. **最近使用**——需要一张跨形态的 usage 表（现有 `call_count` 只覆盖工具型）。本次不做。

### 3.2 卡片解剖

```
┌──────────────────────────────┐
│ [🛠]  日志分析        [公测] │   图标 + 名称 + 形态徽标 + 状态徽标
│       工具 · Trace 诊断       │   形态在前，域标签在后（版本号下沉详情页）
│                               │
│ 贴 kernel ring buffer…        │   摘要 1–2 行
│                               │
│ #日志 #诊断 #Demo             │   域标签
│ ────────────────────────────  │
│ 🔧 Dify · 🕐 3 小时前         │   按形态变化的 meta 行
│ 开始使用 ›                    │   CTA（点下去会发生什么）
└──────────────────────────────┘
```

meta 行按形态取**真实数据**（不是静态文案）：

| kind | 数据来源 | 显示 |
|---|---|---|
| tool | 能力记录自带 | 引擎 · 最近使用 · 调用次数 |
| board | `GET /review-agent/overview` | 数据源 · 覆盖 MR 数 |
| catalog | `GET /assets` | 插件/技能/连接器计数 · 待审数 |
| library | `GET /kb/datasets` | 数据集 · 文档 · 分段 |

取数失败一律降级为 `—`，**不阻塞卡片渲染**。

## 四、侧栏 = 能力导航器

侧栏从「页面导航」改成「能力导航器」：

```
全部能力                      ← 回首页
─────────
🛠 工具
  日志分析
  用例生成
🧬 看板
  代码检视
🗂 目录
  资产市场
📚 知识
  知识库存
─────────
📡 服务状态
RAGFlow    正常
Dify       正常
ReviewAgent 未配置
```

理由：侧栏 = 功能目录，首页 = 总览，两者**共用同一份能力数据**，不会出现"侧栏有、首页没有"。知识库存从此不再是平级分区，就是列表里的一张卡。

底部服务状态面板（`AppSidebar.vue` 现有实现）拆成独立组件 `ServiceStatus.vue`，职责单一。

## 五、详情页统一外壳

现在三个详情页各写各的头部（AgentRunner / CodeReviewV2 / Market 都是手写的 `.run-hd`），知识库页干脆没有头部。统一成 `components/CapabilityShell.vue`：

```
← 返回工作台 │ [🛠] 日志分析  工具 · 公测        [可选动作区]
             │ 贴 kernel ring buffer…
```

四个详情页都套这个外壳 → 切能力时视觉连续。**外壳不自己取数**，由页面把自己已知的 name/icon/kind/status/summary 传进来（避免每个详情页多打一次 API）。

## 六、匿名策略

首页**匿名开放只读**：看得见能力清单与形态，**点进去需要登录**。

- 后端 `GET /agents` 从 `get_current_user` 改成 `get_optional_user`（该函数已存在，无 token / 无效 token → anonymous 占位用户）。
- 前端 axios 拦截器把首页路径纳入 `publicRead` 路由：登录用户用 user token，匿名用户用 `VITE_ANONYMOUS_READ_TOKEN`。
- 匿名点非公开能力 → 跳 `/login?redirect=<目标>`；`code-review` 保持匿名可看（现状不变）。

## 十、验收标准

1. 首页 `/` 渲染能力墙；`/plaza` 重定向到 `/`，旧书签不 404。
2. 匿名访问 `/`：能看到全部能力卡（含知识库存），点进非公开能力被引导到登录页；`/code-review` 仍匿名可看。
3. 侧栏按形态分组列出能力，当前能力高亮；底部服务状态面板功能不变。
4. 四种形态的卡片 meta 取真实数据，取数失败降级不报错。
5. 规划中的能力沉底、不可点、显示"规划中"。
6. 四个详情页头部一致，均为"← 返回工作台"。
7. 全站用户可见文案不再出现"智能体广场"；用户侧不出现"智能体"。
8. `vitest run` 全绿（新增单测覆盖形态常量、CapabilityCard、Home、CapabilityNav、CapabilityShell）；后端 `pytest` 全绿；`npm run build`（含 `vue-tsc --noEmit`）通过。
