# 能力墙重排 —— 2026-10-27

> 一句话: **能力墙的分组、角色名和卡片清单都重排了一遍** —— 让用户先看到"平台能给我什么(资产)",
> 再看"平台能替我干什么(工具)"、"平台上有什么数(看板)"。

---

## 一、这轮改了什么

| # | 改动 | 为什么 |
|---|---|---|
| ① | **工具组只留「环境运维」** | 日志分析 / 测试方案生成 / 文本用例生成 都是"规划中"状态 —— 挂在侧栏里占位又点不动, 用户只会以为平台坏了 |
| ② | **「环境运维」文案重写** | 老文案塞了温箱、环境分析(温度/功耗/吞吐) —— 那是"看趋势"的活, 跟"查一下状态 / 跑一个动作"的运维不是一回事 |
| ③ | **角色名「底座」→「资产」** | "底座"说的是**架构位置**(谁垫在底下), 用户看不懂; "资产"说的是**这里放的是可复用的东西** |
| ④ | **资产组排最上面** | 用户先看到"平台能给我什么", 再看"平台能替我干什么" |
| ⑤ | **「AI 资产市场」→「插件·技能·连接」** | 老名字里的"AI 资产"跟角色名"资产"撞了 —— 用户分不清"资产市场"卖的是不是"资产"这个角色。新名字直接说清卖什么 |
| ⑥ | **新增「软件库」卡** | 存公司内部的软件(展示功能 / 详情 / 适用 / 发布更新说明) —— 跟"插件·技能·连接"是两回事: 那是装进 Agent 的扩展, 这是给人用的软件 |

## 三、「环境运维」的文案为什么这么写

**老文案**(已废):
> 环境运维: 查询测试机状态 / 温箱与通道占用 / 环境分析 (温度/功耗/吞吐), 一键执行常用运维命令 (拉日志 / 复位 / 升级 FW)

问题: "温箱与通道占用"和"环境分析(温度/功耗/吞吐)"是**看趋势**的活 —— 要长周期盯着,
跟"查一下状态 / 跑一个动作"的运维是两回事。混在一张卡上, 这张卡既不像运维也不像环境监控。

**新文案**:
> **环境运维**: 基本的服务操作 + SSD 盘符/设备运维 —— 查状态 / 拉日志 / 复位 / 升级固件 / 重启服务, 由 AI 辅助下发与解读
> - 什么时候用: 要看某台机台上 SSD 盘符/设备的状态, 或顺手执行一个常用运维动作
> - 不适合: 要派发长时批处理任务, 或只想拿原始日志自己判读

单测盯着这几条 (`backend_gateway/tests/test_capabilities.py`):
- 文案里**不许**出现「温箱」「老化」「温度」「功耗」;
- 但**必须**出现「服务」「SSD」「AI」—— 该说的不能被改没了。

## 五、⚠️ 踩过的坑

**给 `AgentCategory` 加了新值, 忘了 MySQL 的 category 是 ENUM 列。**
后端启动时的 `seed_agents()` 插 `software-library` → `DataError (1265): Data truncated for
column 'category'` → **应用启动失败, 进程直接退出**(launchd 会反复拉起, 但起不来)。

跟以前加 `ai_market`(0004)、`ssd_kb`(0017) 时一模一样 —— **每次给 AgentCategory 加值,
都得配一个 alembic 迁移改 ENUM 列定义**, 而且 DB 侧写的是 **name(下划线)** 不是 value(连字符):
Python 侧 `sw_library = "sw-library"`, DB 侧必须写 `'sw_library'`。

新增业务域的完整清单:
1. `app/models/agent.py` 加枚举值;
2. 写 alembic 迁移 `ALTER TABLE agents MODIFY COLUMN category ENUM(...)`;
3. 前端 `CATEGORY_LABELS` 加中文名;
4. 跑一次后端 —— 忘了第 2 步就起不来。
